TOOL: write_file

DESCRIPTION:
Write content to a file. Creates parent directories if needed.

WHEN TO USE:
- Creating new files
- Overwriting entire file content
- After understanding existing code structure (search first!)
- When user explicitly says "create", "write", "add a file"

DO NOT USE WHEN:
- Making small edits to existing files (use apply_patch)
- Without first reading/searching the file (may overwrite important code)
- On files outside project root (security violation)
- On config files without user confirmation
- Path is absolute (starts with /) — ALWAYS use relative paths

EXAMPLES:
User: "create a new component Button.tsx"
-> write_file({"path": "src/components/Button.tsx", "content": "<Button component...>"})

User: "add a README explaining the project"
-> write_file({"path": "README.md", "content": "# Project\n\nDescription..."})

User: "crea index.html"
-> write_file({"path": "index.html", "content": "<!DOCTYPE html>..."})

User: "crea landing page en carpeta medicina"
-> write_file({"path": "medicina/index.html", "content": "<!DOCTYPE html>..."})

User: "crea carpeta src con main.js"
-> write_file({"path": "src/main.js", "content": "console.log('hello');"})

SCHEMA:
{
  "type": "object",
  "properties": {
    "path": {
      "type": "string",
      "description": "Relative path from project root"
    },
    "content": {
      "type": "string",
      "description": "Full file content"
    }
  },
  "required": ["path", "content"]
}

VALIDATION:
After write_file, always run appropriate validation:
- Rust: cargo check
- TypeScript: tsc --noEmit
- Python: python -m py_compile
- Tests: cargo test / npm test / pytest
